# uSDX ESP32 firmware port

Базовый перенос выбранного исходника PE1NNZ uSDX 1.02x на ESP32-WROOM-32U / ESP32 DevKit V4.

- Исходная версия: `bf8acd31b8a2506c4e1d203dfb283feecae947e1`
- Основной скетч: `uSDX_ESP32.ino`
- Точная неизменённая копия исходников лежит в `firmware/reference/PE1NNZ_bf8acd31b8/`.
- ESP32 Arduino Core: 3.3.13
- Плата для первой сборки: `esp32:esp32:esp32` (ESP32 Dev Module)

## Что сделано в первом проходе

- Снят жёсткий запрет на архитектуру, разрешён ESP32.
- Оставлены исходные RX/TX DSP функции и состояние фильтров.
- Добавлен `usdx_esp32_hal.h`: ADC1 через ESP-IDF one-shot driver, EEPROM-эмуляция с AVR-совместимым block API, GPIO-план, LEDC PWM, GPTimer и планировщик DSP-задачи.
- Si5351 и расширитель LPF переведены на аппаратный `Wire`.
- AVR Timer2 заменён GPTimer ESP32 с разрешением счётчика 10 MHz: аппаратное прерывание будит высокоприоритетную задачу; сама DSP-обработка, ADC one-shot и I²C выполняются в контексте задачи, не в ISR.
- Частый ADC-путь заранее настраивает ADC1_CH0/3/6 и читает текущий канал по `ADMUX` через `adc_oneshot_read()`. Результат масштабируется 12→10 бит для сохранения диапазона оригинального uSDX.
- I²C адаптер поддерживает как одно-байтовые чтения Si5351, так и два байта, требуемые необязательным INA219.
- AVR Timer1 PWM заменён двумя каналами LEDC (8 бит).
- В первом профиле отключены аппаратная самодиагностика DIAG, CAT и CW decoder; дисплей временно headless (`BLIND`). RX, SSB TX, keyer и исходные DSP-алгоритмы оставлены.
- Добавлена GitHub Actions сборка под Arduino-ESP32 3.3.13.

## Предварительная распиновка

| Функция | GPIO ESP32 | Комментарий |
|---|---:|---|
| RX I input | 36 | ADC1_CH0 / VP |
| RX Q input | 39 | ADC1_CH3 / VN |
| Microphone input | 34 | ADC1_CH6 |
| Audio PWM output | 25 | LEDC, 8 bit, исходная частота 78.125 kHz |
| PA PWM / envelope | 26 | LEDC, 8 bit |
| Si5351 SDA | 21 | I²C |
| Si5351 SCL | 22 | I²C |
| RX/TX control | 27 | GPIO |
| DIT / DAH | 32 / 33 | keyer inputs |
| Rotary A / B | 18 / 19 | interrupt inputs |
| Button | 23 | `INPUT_PULLDOWN` by default; active-high, matches original `inv=0` logic |
| Signal output | 4 | GPIO |

Это стартовая карта выводов для первой сборки, а не подтверждённая схема подключения радиотракта. Входы ESP32 не 5-вольт-совместимые. Не подключайте непосредственно сигналы старой AVR-платы, если их максимальный уровень и смещение по постоянному току не проверены: особенно I/Q и микрофон, обычно смещённые к половине 5-вольтового питания в AVR-схеме. Все сигналы должны оставаться в допустимом диапазоне ESP32. Перед подключением PA проверьте логические уровни и назначение управляющего сигнала на GPIO26.

В коде оригинала `admux[0]` используется Q-обработчиком, а `admux[1]` — I-обработчиком. Поэтому HAL сопоставляет канал 0 с GPIO39 (Q), а канал 1 с GPIO36 (I).

## EEPROM и настройки

Оригинальный `eeprom_read_block()` / `eeprom_write_block()` заменён совместимыми функциями поверх ESP32 `EEPROM` emulation. Используется 4096-byte storage, исходный `EEPROM_OFFSET=0x150` и тот же бинарный формат полей параметров. Записи коммитятся блоком после изменения; перед первым использованием радио настройки будут считаны как `0xFF`, что активирует исходную процедуру инициализации заводских параметров.

## Что ещё не подтверждено

- Успешная сборка Arduino-ESP32 3.3.13 (CI workflow добавлен, результат нужно проверить).
- Реальная пропускная способность и стабильность `adc_oneshot_read()` на частоте 62.5 ksample events/s; при нехватке времени потребуется непрерывный ADC/DMA, а не `analogRead()` в каждом цикле.
- Джиттер таймера/задачи и отсутствие пропущенных событий при полной RX нагрузке.
- Корректность уровня и спектра PWM аудио и PA.
- Проверка PLL I²C обновлений во время SSB TX.
- Реальная распиновка радиоплаты: GPIO назначены как стартовый шаблон, их необходимо согласовать с электрической схемой.

Важно: текущий HAL — первый функциональный слой адаптации. Он ещё не является доказанным real-time решением. ADC one-shot вызывается из высокоприоритетной задачи, поскольку ESP-IDF запрещает вызывать этот драйвер из ISR; документация также указывает, что чтение выполняется polling-методом. Поэтому сборка сама по себе не докажет соблюдение 16-микросекундного периода RX. Сначала нужно получить успешную сборку, затем проверить время callback, отсутствие накопления очереди и качество RX/TX на плате.
