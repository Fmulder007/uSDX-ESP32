# План эталонных DSP-тестов

**Статус:** план испытаний; тестовый стенд ещё не реализован.  
**Цель:** получить воспроизводимые цифровые результаты до переноса алгоритмов на ESP32.

## 1. Базовые правила

- Все тесты используют зафиксированный source commit bf8acd31b8a2506c4e1d203dfb283feecae947e1.
- Входные массивы deterministic: одинаковые файлы входа должны давать одинаковый результат.
- Результаты сравнивать по этапам, а не только по конечному звуку.
- Режимные настройки фиксировать в каждом тесте; не полагаться на значения, загружаемые из EEPROM.
- Для каждого теста сохранять input, config и expected output.
- Не менять коэффициенты и порядок операций в процессе переноса без отдельного протокола сравнения.

## 2. Формат тестовых данных RX

Базовый source-compatible формат входа:
- последовательность raw ADC events;
- событие имеет номер, канал I/Q и центрированный signed sample;
- порядок событий соответствует исходной последовательности I,Q,I,Q,...;
- значения передаются в том виде, который возвращает исходник после вычитания ADC bias.

Для начала достаточно двух представлений:
1. CSV/текстовый набор для ручной проверки и графиков.
2. бинарный или массивный формат для быстрого host-side теста.

Точный формат хранения пока не выбран.

## 3. RX — этапы и тестовые сигналы

### RX-0: вход и выравнивание I/Q
- Проверить pipeline: обработчик выставляет ADMUX для следующей конверсии, но читает предыдущий ADC result.
- На старте отдельно определить, какой первый ADC result попадает в CIC.
- Нулевые входы.
- Постоянный уровень на I и Q.
- Разные постоянные уровни на I и Q.
- Линейный ramp по времени.
- Импульс отдельно в I, отдельно в Q.
- Чередующиеся каналы с известной временной фазой.

Проверить результат midpoint interpolation I и последовательность ADC pipeline.

### RX-1: CIC
- Один импульс на каждом возможном временном слоте I.
- Один импульс на каждом возможном временном слоте Q.
- Ступенька и постоянный вход.
- Синусоиды низкой частоты и около границы пропускания.
- Псевдослучайная последовательность с фиксированным seed.

Сверять:
- состояние после каждой из восьми фаз;
- промежуточные uI/uQ;
- итоговые i_ac2/q_ac2;
- выходы после att2;
- порядок и момент выдачи пары.

### RX-2: Hilbert и I delay
Подать тоны по полосе и проверить:
- I/Q амплитуду;
- квадратурную фазовую разность;
- задержку;
- знак qh;
- согласование I delay с Hilbert group delay.

Отдельно проверить синус и косинус с одинаковой частотой и известным фазовым сдвигом.

### RX-3: демодуляция
Для USB/LSB:
- тон в нижней и верхней части полосы;
- одинаковая амплитуда при разных частотах;
- проверка знака боковой полосы.

AM/FM ветви проверять отдельно после базового SSB.

### RX-4: AGC/NR/IIR
Сначала тестировать без AGC/NR/filter. Затем включать по одному:
- fast AGC;
- alternative AGC, если его решено сохранить;
- NR;
- каждый IIR filter.

Сверять внутреннее состояние, не только аудиоамплитуду.

### RX-5: аудиовыход
Отдельно подать известный audio sample stream в Comb/integrator interpolator и проверить все выходные обновления PWM duty. Carrier frequency и duty update rate измерять независимо.

## 4. TX — этапы и тестовые сигналы

### TX-0: microphone input conditioning
- тишина / DC;
- step;
- импульс;
- синус фиксированной амплитуды;
- несколько амплитуд около low-level threshold.

Сначала проверить модель усреднения ADC отдельно от ssb(). Воспроизвести точную последовательность четырёх чтений: первое до PLL I2C send, второе после него, третье после ssb(), четвёртое после freq_calc_fast(). Не заменять её равномерными четырьмя соседними samples.

### TX-1: mic filter и Hilbert
Сравнить значения:
- после LPF;
- после DC removal;
- каждого значения истории v[16];
- I и Q Hilbert outputs.

### TX-2: amplitude и phase
Сверить:
- magn(i,q);
- arctan3(q,i);
- phase;
- prev_phase;
- dp после wrap;
- dp после MAX_DP;
- frequency_delta;
- amp до и после LUT.

Обязательные тесты: полный оборот фазы, переход через ноль, малые амплитуды и резкие изменения входа.

### TX-3: pipeline и hardware adapter
Разделить:
- момент поступления микрофонных данных;
- момент готовности frequency_delta/amplitude;
- момент применения частотной команды Si5351;
- момент обновления PA PWM.

Проверить sample delay и допустимый jitter. Не смешивать DSP output с I2C transaction time.

## 5. Численная совместимость

Для каждого этапа хранить два результата, если они различаются:
- фактическое поведение AVR reference;
- целевой результат ESP32 implementation.

Критерии:
- сначала добиться точного совпадения в специально выбранной reference arithmetic модели;
- если точное совпадение недостижимо или нецелесообразно, описать конкретные расхождения, их причины и спектральное влияние;
- не объявлять «эквивалентно» только потому, что на слух результат похож.

## 6. Формат эталонных файлов

Предлагаемый будущий каталог:

    temp/reference/
      rx/
        input/
        expected/
      tx/
        input/
        expected/
      README.md

Для каждого набора рядом хранить описание:
- sample rate и порядок каналов;
- формат чисел;
- конфигурацию DSP;
- количество входных и выходных отсчётов;
- ожидаемую контрольную сумму или точное содержимое результата;
- источник expected output и способ его получения.

Пока эти файлы не созданы, потому что сначала нужно закончить точную спецификацию арифметики и timing.

## 7. Критерии завершения reference этапа

- sample API и block API дают одинаковый результат на одинаковой последовательности;
- каждый этап RX/TX имеет отдельный эталон;
- state initialization/resume поведение документировано;
- различия AVR и ESP32 объяснены;
- базовые SSB RX/TX выходы воспроизводимы;
- есть количественный тест спектра и бокового подавления.

После выполнения этих условий можно начинать портирование DSP на ESP32.
