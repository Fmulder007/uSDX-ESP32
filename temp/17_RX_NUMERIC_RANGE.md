# RX numeric range: CIC, Hilbert и SSB IIR intermediate width

**Источник:** PE1NNZ uSDX, commit bf8acd31b8a2506c4e1d203dfb283feecae947e1.
**Статус:** диапазон активной CIC-цепочки доказан для 10-bit ADC domain; обнаружен воспроизводимый выход промежуточной Hilbert-арифметики за signed int16. Фактический результат AVR-GCC при signed overflow ещё не снят.

## 1. Диапазон входа CIC

ADC path возвращает ADC - 511. Для 10-bit ADC это целые значения:

- минимум: 0 - 511 = -511;
- максимум: 1023 - 511 = 512.

I midpoint interpolation (prev_adc + adc) / 2 остаётся в том же диапазоне, если оба ADC результата принадлежат ему.

## 2. CIC: промежуточные суммы безопасны в int16

Один активный FIR этап имеет коэффициенты [1, 3, 3, 1], сумма абсолютных коэффициентов и DC gain равны 8. Между ступенями стоит M_SR=1, то есть арифметический сдвиг вправо на один бит.

| Узел | Граница при ADC input [-511, 512] | Signed int16 |
|---|---:|---|
| Сумма первой FIR-ступени до >>1 | [-4088, 4096] | помещается |
| Выход первой ступени после >>1 | [-2044, 2048] | помещается |
| Сумма второй FIR-ступени / raw CIC output | [-16352, 16384] | помещается |
| Q/I после att2=2 | [-4088, 4096] | помещается |

Это консервативные коэффициентные границы: история фильтра не может выйти за исходный диапазон, если начальные состояния также нулевые или ранее сформированы допустимыми входами. Исполняемый тест постоянного максимального входа подтверждает установившиеся границы: +512 → +16384, -511 → -16352.

### DC gain

Для постоянного входа:

- первая ступень: 8 / 2 = 4;
- вторая ступень: 8;
- raw CIC gain до att2: 4 × 8 = 32;
- при default att2=2: дополнительное деление на 4, итоговый DC gain после process() равен 8.

В dB для амплитудного отношения это соответственно около **30,10 dB raw** и **18,06 dB после default att2**. Каждый шаг att2 — ещё примерно 6,02 dB цифрового ослабления.

Дополнительный source cross-check: smeter() умножает уровень обратно на (1 << att2), а затем нормирует через R * 8. При R=4 это 32, что совпадает с рассчитанным raw DC gain активной CIC-цепочки. Это внутренняя согласованность калибровки, а не доказательство смысла комментария.

Исходный комментарий рядом с #define R 4 говорит “providing 12dB gain” и одновременно называет фильтр “2nd Order CIC”. Он не описывает полный активный коэффициентный DC gain 32; активная реализация ниже помечена M_SR=1, CIC N=3. 12 dB численно соответствует амплитудному отношению 4, но почему автор использовал именно эту формулировку — неизвестно. Возможно, комментарий остался от другой версии фильтра. **Не использовать 12 dB как scaling coefficient.**

att2 по умолчанию равен 2, но это не жёсткий минимум: меню ATT2 допускает значения 0…16. Поэтому проверку Hilbert нельзя ограничить только штатной настройкой.

## 3. Hilbert: промежуточные выражения могут выйти за int16

После att2=2 значения Q history лежат в пределах [-4088, 4096]. В активной формуле Hilbert есть:

- разности двух history samples;
- умножение (v[4] - v[10]) * 5;
- последующее вычитание (v[6] - v[8]).

Сами history samples помещаются в int16, но произведение и третий числитель уже не обязаны помещаться. Это не абстрактная комбинация независимых предельных значений: найден воспроизводимый пример, полученный на входе через текущую восьмифазную CIC-модель.

### Воспроизводимый пример

Вход: полноамплитудная синусоида 650 Hz, амплитуда 511 ADC counts, частота Q-входа 31 250 samples/s. Используется default att2=2. Это соответствует нижней границе диапазона 650…3400 Hz, указанного исходным комментарием к Hilbert.

На первом обнаруженном выходе с входным индексом 56:

| Величина | Значение |
|---|---:|
| v[4] - v[10] | 7758 |
| v[6] - v[8] | 3875 |
| (v[4] - v[10]) * 5 | **38790** |
| (... * 5) - (v[6] - v[8]) | **34915** |

Оба выделенных промежуточных значения выше 32767. При математике Python текущая Hilbert-модель получает для этого момента qh=3890.

Если исключительно для иллюстрации применить modulo-16-bit wrap к третьему числителю, 34915 превратится в -30621; третий член изменится с +272 на -239, а qh — с 3890 на 3379 (разница 511 counts).

Это **не утверждение**, что AVR-GCC обязательно сформировал именно такой wrap. Переполнение signed int в C/C++ не является определённой операцией языка; результат должен быть установлен для конкретной сборки/инструкций. Пример показывает, что имеющаяся Python reference model с неограниченными промежуточными целыми не может считаться бит-точной моделью исходной AVR-прошивки.

## 4. Что означают текущие Python-модели

- rx_cic.py — математическая модель расписания CIC; для допустимого входа рассчитанные CIC промежуточные значения укладываются в int16.
- rx_quadrature.py — сохраняет порядок выражения и C-style truncation делений, но Python использует неограниченные целые. Это **wide-intermediate mathematical baseline**, а не AVR overflow emulator.
- rx_numeric_audit.py — выводит промежуточные Hilbert значения и отмечает выход за signed int16. hilbert_int16_wrap_hypothesis() — только кандидат modulo-арифметики, не подтверждённая модель AVR-GCC.

В test_rx_numeric_audit.py добавлены проверки CIC DC gain/границ, воспроизводимого 650 Hz overflow и различия между wide baseline и простым wrap-кандидатом.

## 5. Что нужно выяснить до переноса

1. Получить точную версию AVR-GCC и параметры оптимизации исходной сборки, включая действующий pragma GCC optimize("Ofast").
2. Собрать небольшой reproducer именно третьего Hilbert выражения и посмотреть AVR disassembly.
3. На фиксированном входном векторе сравнить реальный AVR output с wide reference и wrap candidate.
4. Только после этого выбрать ESP32 арифметику: точное воспроизведение фактического AVR binary behavior либо осознанное wide-int32 исправление с документированным отличием.

До выполнения этих пунктов нельзя самовольно менять int16_t на int32_t, добавлять saturation или считать wrap эталоном.

## 6. AVR probe для следующего этапа

В репозитории подготовлены:

- reference/avr_hilbert_probe.c — source-style выражение с pragma Ofast и отдельный int32 wide вариант;
- reference/avr_hilbert_probe.md — команды сборки, извлечения disassembly и точки чтения результатов.

Probe намеренно требует AVR target и проверяет sizeof(int) через INT_MAX. Его результат пока не получен: в текущем исследовательском окружении AVR-GCC отсутствует. Инструкция сохранена, чтобы следующий запуск не требовал повторно восстанавливать входной вектор и формулу.

## 7. SSB IIR: отдельный reachable overrange

Диапазонный аудит SSB IIR вынесен в подробный разбор [18_RX_POST_NR_IIR.md](18_RX_POST_NR_IIR.md). Для входа filt_var() — синус 2,5 kHz с амплитудой 512 при fs=7812,5 Hz — общая prefilter sum достигает 37315 во всех трёх SSB-фильтрах. У filt=1 отдельное умножение 18*zc1 достигает 46980, а stage-2 feedback sum — 43357. Использована wide Python recurrence; AVR result after signed overflow remains unknown. Это показывает, что numeric compatibility issue затрагивает не только Hilbert, но и активный SSB IIR.
