# Численная точность host-side reference-моделей

**Назначение:** явно отделить проверку математической структуры DSP от точного воспроизведения арифметики исходной AVR-сборки.  
**Источник алгоритмов:** PE1NNZ uSDX, commit bf8acd31b8a2506c4e1d203dfb283feecae947e1.

## 1. Что уже воспроизводят текущие Python-модели

- Порядок восьми фаз RX CIC и владельцев регистров состояния.
- Положение выдачи пары I/Q и конвейерное использование q_ac2.
- Отдельные сдвиги/масштабы в CIC.
- Логический MUX/read-previous ADC pipeline.
- Midpoint interpolation I с делением signed integer к нулю.
- Порядок обновления Hilbert Q history и I delay.
- Четыре отдельных деления Hilbert выражения, каждое с truncation toward zero.
- Базовая SSB post-processing ветка, включая явный wrap_i16 для ключевого AGC произведения и состояния gain.

## 2. Что пока не воспроизводится побитово

Python int имеет неограниченную точность. AVR-GCC на целевой ATmega328P использует 16-разрядный int. Поэтому некоторые промежуточные операции на AVR могут переполняться или сужаться раньше, чем аналогичная Python expression.

Текущие модели не являются точной эмуляцией:
- AVR integer promotions;
- 16-bit signed overflow в каждом промежуточном выражении;
- compiler-specific оптимизаций/assumptions;
- всех точек сужения результата;
- целочисленных преобразований в TX Hilbert и atan2 macro;
- возможного расхождения C abstract machine и конкретного AVR-GCC результата.

Даже если вход/выход функции имеет тип int16_t, промежуточные операции могут вычисляться как int; на AVR этот int также 16-разрядный. Нельзя автоматически считать, что все суммирования выполняются в 32 bit.

## 3. Повышенный риск — RX Hilbert

Активная формула qh включает выражения типа:

    (v[0] - q_ac2) + (v[2] - v[12]) * 4

После CIC и att2 отдельные v могут оставаться в диапазоне нескольких тысяч. Разности и умножение на коэффициенты способны выйти за диапазон signed 16-bit для некоторых входов. Python reference сохраняет порядок отдельных делений, но промежуточные суммы пока не заворачиваются в AVR int16.

Следовательно:
- impulse response test проверяет коэффициентный порядок и задержку;
- он сам по себе не доказывает AVR arithmetic equivalence;
- перед утверждением numerical match нужен range analysis и golden comparison.

## 4. Повышенный риск — TX Hilbert и atan2

В TX:
- 16-value mic history;
- Hilbert sums with coefficients;
- atan2 macro expands its argument textually;
- phase delta and MAX_DP.

В arctan3() нельзя предварительно вычислять целочисленный ratio z без проверки: макросная подстановка меняет порядок умножения и деления. Этот вопрос описан отдельно в [02_TX_PATH.md](02_TX_PATH.md) и [13_TX_PHASE_SCALING.md](13_TX_PHASE_SCALING.md).

Даже при правильном текстовом раскрытии остаётся вопрос ширины промежуточных signed int.

## 5. Три численных варианта для ESP32

### A. Wide mathematical reference
Использовать int32_t/int64_t для промежуточных результатов. Это удобно для анализа идеальной математики и предотвращения overflow.

Но это не обязательно повторяет оригинальный AVR result.

### B. AVR behavior emulation
Явно повторять фактическую ширину и точки wrap/narrowing исходной AVR-сборки. Для спорных выражений сравнить с результатами, полученными целевым AVR compiler/runtime.

Преимущество — наиболее вероятная совместимость с исходным радио. Недостаток — нужен точный toolchain/build configuration и анализ overflow.

### C. Documented fixed-point redesign
Выбрать контролируемые ширины аккумуляторов, rounding и saturation для ESP32. Это может дать более надёжный DSP, но будет изменением алгоритма/численного поведения и требует спектральных тестов.

Не выбирать C автоматически, даже если он кажется «правильнее».

## 6. Предлагаемый порядок численной проверки

1. Зафиксировать точные версии и flags AVR compiler/board package исходного проекта.
2. Создать небольшой host/AVR test harness с фиксированными входными векторами.
3. Снять промежуточные результаты AVR для CIC, Hilbert, AGC, IIR, TX Hilbert, atan2 и dp.
4. Сверить Python wide reference.
5. Создать отдельную AVR-width emulation модель и сверить с golden outputs.
6. Выбрать source-compatible или redesigned numeric path для ESP32 по каждому блоку отдельно.
7. Все изменения коэффициентов, rounding и saturation оформлять как отдельный вариант, не переписывая baseline reference.

## 7. Как читать статус текущих моделей

Текущий RX SSB chain полезен для проверки:
- временной последовательности;
- MUX state machine;
- CIC polyphase order;
- I/Q phase alignment;
- разделения функциональных стадий;
- базового контроля sample stream.

Но пока он не должен обозначаться как bit-exact AVR reference.

Python tests passed и AVR bit-identical — разные критерии. Полный запуск Python unittest из исследовательской среды также пока не выполнен из-за недоступности GitHub DNS; тесты сохранены и могут быть запущены локально.
