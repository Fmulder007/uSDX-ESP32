# Жизненный цикл состояния DSP в исходном uSDX

**Источник:** PE1NNZ uSDX, commit bf8acd31b8a2506c4e1d203dfb283feecae947e1.  
**Статус:** разбор по исходнику; намерение автора относительно сохранения части истории при TX/RX switching не установлено.  
**Цель:** не потерять скрытое static-состояние при выделении DSP в отдельные структуры.

## 1. Три разных события, которые нельзя смешивать

1. **Cold start MCU** — C/C++ runtime инициализирует глобальную/static память: переменные с явными начальными значениями получают их, остальные static/global объекты начинают с нуля.
2. **RX start/resume** — вызывается start_rx() или возврат в RX через switch_rxtx(); это не полный reset всех DSP-фильтров.
3. **DSP block reset** — будущая явная операция в нашем коде; её семантику мы должны определить отдельно.

В исходнике нет универсальной функции, которая обнуляет всё состояние RX/TX DSP при каждом переходе режима.

## 2. Что сбрасывается при входе в RX

start_rx():
- устанавливает _init = 1;
- устанавливает rx_state = 0;
- устанавливает func_ptr = sdr_rx_00;
- настраивает ADC mux;
- запускает Timer1 и Timer2.

При возврате из TX в RX switch_rxtx():
- выбирает func_ptr = sdr_rx_00 (с учётом специальных CW/QSK случаев);
- устанавливает _init = 1;
- устанавливает rx_state = 0.

Для активной NEW_RX=1 переменная _init фактически обрабатывается в двух точках:

### В sdr_rx_common_i()
При _init обнуляются:
- ocomb;
- ozi1;
- ozi2.

### В process()
При _init обнуляются:
- ac3;
- ozd1;
- ozd2.

После этого process() снимает _init = 0.

Это сбрасывает часть аудиовыходного интерполятора, но не всю RX-историю.

Источники: [start_rx()](https://github.com/threeme3/usdx/blob/bf8acd31b8/usdx.ino#L3538-L3555), [switch_rxtx()](https://github.com/threeme3/usdx/blob/bf8acd31b8/usdx.ino#L3560-L3630), [process()](https://github.com/threeme3/usdx/blob/bf8acd31b8/usdx.ino#L2746-L2788), [sdr_rx_common_i()](https://github.com/threeme3/usdx/blob/bf8acd31b8/usdx.ino#L2850-L2880).

## 3. Что не сбрасывается при обычном RX resume

В активной ветке явного присваивания нуля при _init не найдено для:

| Состояние | Назначение |
|---|---|
| i_s0za1/i_s0zb0/i_s0zb1 | CIC I, первая ступень |
| i_s1za1/i_s1zb0/i_s1zb1 | CIC I, вторая ступень |
| q_s0za1/q_s0zb0/q_s0zb1 | CIC Q, первая ступень |
| q_s1za1/q_s1zb0/q_s1zb1 | CIC Q, вторая ступень |
| q_ac2 | последний Q-результат |
| v[14] в process() | история Hilbert Q |
| v[7] в process() | задержка I |
| prev_adc в sdr_rx_common_i() | предыдущий I sample для interpolation |
| absavg256cnt и absavg256 | статистика уровня |

Эти значения получают нулевое начальное состояние после cold start, поскольку являются static/global, но продолжают жить при последующих вызовах start_rx()/switch_rxtx().

Практическое следствие: при переходе TX→RX CIC/Hilbert могут продолжить работу со старой историей, которая осталась до TX. Это наблюдаемое поведение исходника; является ли оно намеренным, код сам по себе не доказывает.

## 4. Состояние slow_dsp и фильтров

### AGC
- process_agc_fast() использует глобальный gain, исходное значение 1024.
- process_agc() использует centiGain (исходное значение 128), decayCount (400) и локальный static small.
- В стандартной compile-time конфигурации FAST_AGC выключен, agc изначально равен 1; это выбирает process_agc_fast().
- Параметры могут изменяться через меню/EEPROM.

### NR
- Активная process_nr() содержит static ea1.
- При nr=0 она не вызывается.
- При включении NR ea1 начинает обновляться; выключение NR не сбрасывает ea1, поскольку reset в коде не найден.

### AM/FM демодуляторы
- AM branch slow_dsp() содержит static dc.
- FM branch содержит static zi.
- Эти состояния остаются между переключениями mode, если не происходит cold start; явный reset при смене mode не найден.

### IIR filt_var()
В usdx_filter.h внутри filt_var() находятся static:
- za1, za2;
- zb0, zb1, zb2;
- zc0, zc1, zc2;
- zz1, zz2 для SSB high-pass section.

Если filt == 0, функция не вызывается. Когда фильтр снова включается, сохранённая история не обнуляется. При изменении номера фильтра коэффициенты меняются, но общие static history registers продолжают жить. Это может создавать переходной процесс и должно быть включено в reference tests.

Источники: [AGC/NR/slow_dsp](https://github.com/threeme3/usdx/blob/bf8acd31b8/usdx.ino#L2420-L2665), [IIR state](https://github.com/threeme3/usdx/blob/bf8acd31b8/usdx_filter.h#L45-L135).

## 5. TX SSB state

В ssb() находятся:
- static dc;
- static z1;
- static v[16];
- static prev_phase.

Эти значения обнуляются только при cold start MCU. В dsp_tx() или switch_rxtx() явного сброса этих внутренних static-переменных не видно.

Следовательно, второй и последующие TX-сеансы могут продолжать историю микрофонного фильтра и фазового расчёта с предыдущего сеанса. Это необходимо сохранить в source-compatible варианте или явно изменить как отдельный проверяемый вариант.

LUT amp mapping формируется build_lut() при setup; это не динамическая история фильтра, а таблица конфигурации.

Источник: [ssb()](https://github.com/threeme3/usdx/blob/bf8acd31b8/usdx.ino#L1961-L2035), [build_lut()](https://github.com/threeme3/usdx/blob/bf8acd31b8/usdx.ino#L4590-L4600).

## 6. Runtime параметры — отдельно от DSP state

Некоторые значения имеют начальные значения в глобальных объявлениях, но затем могут быть загружены/перезаписаны в setup():

- mode первоначально USB, затем задаётся из vfomode после загрузки параметров;
- filt первоначально 0, затем управляется режимом/настройками;
- agc первоначально 1 (если FAST_AGC выключен);
- nr первоначально 0, в setup() также выключается;
- att2 первоначально 2;
- drive первоначально 2, затем setup() задаёт drive=4 до загрузки параметров;
- volume первоначально 12;
- tx первоначально 0.

В будущем это должны быть входные конфигурационные параметры DSP, а не незаметные глобальные переменные между RX/TX.

Источник: [инициализация и загрузка параметров](https://github.com/threeme3/usdx/blob/bf8acd31b8/usdx.ino#L4980-L5070).

## 7. Как это оформить в ESP32 API

Предлагаются разные явно названные операции:

| Операция | Назначение |
|---|---|
| cold_init() | Полный старт DSP с нулевым состоянием и начальной конфигурацией |
| source_compatible_resume_rx() | Воспроизводит наблюдаемое исходное RX resume: сбрасывает только source-reset subset |
| reset_rx_all() | Полный reset всех RX CIC/Hilbert/demod/AGC/NR/IIR state |
| reset_tx_all() | Полный reset mic filter, history и phase state |
| set_config() | Изменяет mode/filter/AGC/volume/NR/drive без скрытого сброса состояния |
| reset_filter_state() | Отдельный явный reset IIR/NR/AGC по согласованному правилу |

Нельзя автоматически делать reset_rx_all() на каждый вход в RX: это может изменить исходный переходный процесс.

## 8. Что нужно проверить на эталонной модели

1. Холодный запуск и первые 2–3 CIC output pairs.
2. RX → TX → RX без очистки state.
3. TX → RX после длительной передачи.
4. Повторный TX-сеанс: phase/mic history до и после переключения.
5. Выключение/включение NR: сохраняется ли эффект ea1.
6. Переключение filt 0 → 1 → 0 → 2: поведение общих IIR state.
7. AM → USB → AM и FM → USB → FM: сохраняются ли detector state.
8. Сравнить исходное source-compatible поведение с вариантом полного reset, но не объединять их.

До этих тестов reset semantics в ESP32 DSP API остаётся отдельным конфигурационным решением.
