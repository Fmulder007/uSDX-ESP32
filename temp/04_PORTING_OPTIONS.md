# Варианты архитектуры переноса DSP на ESP32

**Статус:** варианты исследованы на уровне принципов; окончательный механизм ввода аудио и распределение задач ещё не выбраны.

## 1. Что должно остаться неизменным

- Частоты и порядок математических операций исходного DSP фиксируются.
- RX CIC/Hilbert/demod и TX mic/Hilbert/phase calculations тестируются без физического радио.
- Аппаратные драйверы не находятся внутри математических функций.
- Состояние фильтров и буферов явно.
- Результат сравнивается с эталонной моделью исходника.

## 2. Вариант A — почти буквальный перенос по одному отсчёту

Каждое аппаратное событие вызывает обработку одной выборки/одной фазы расписания. Для RX воспроизводится чередование I/Q и CIC расписание; для TX SSB DSP вызывается на каждом цикле 4,8 kHz.

**Плюсы**
- минимальная задержка;
- удобно сопоставлять события с исходником;
- видно соответствие исходной фазовой последовательности.

**Минусы**
- RX событие каждые 16 мкс;
- jitter и высокий приоритет ISR критичны;
- медленные операции и I2C внутри ISR опасны;
- механизм interrupts()/nested ISR не переносится напрямую;
- сложнее изолировать DSP от аппаратуры и RTOS.

**Оценка:** полезен как эталонная модель или тест производительности, но не выбирать заранее окончательной архитектурой.

## 3. Вариант B — DMA и блоковая DSP-обработка

Аппаратная периферия непрерывно заполняет заранее выделенные буферы. По готовности блока DSP обрабатывает массив выборок и передаёт выходной блок дальше.

**Плюсы**
- меньше прерываний на одну выборку;
- понятное владение буферами;
- легко измерять время на блок;
- DSP не зависит от конкретного драйвера;
- удобно запускать одинаковые host-side и ESP32 тесты.

**Минусы**
- появляется блочная задержка;
- нужно подобрать block size;
- нельзя потерять временную последовательность и положение I/Q;
- аппаратный способ получения двух аналоговых каналов ещё не выбран.

Длительность блока на частоте I/Q pairs 7 812,5 Hz:
- 16 пар: около 2,048 ms;
- 32 пары: около 4,096 ms;
- 64 пары: около 8,192 ms.

Для исходного потока ADC events 62,5 kHz размер нужно пересчитывать в исходных событиях, а не в выходных I/Q-парах.

**Оценка:** сильный кандидат для основной реализации, если аппаратный ввод обеспечивает требуемую частоту и согласование I/Q.

## 4. Вариант C — гибрид: аппаратный ввод + ring buffer + DSP task

Узкий ISR или DMA callback только фиксирует готовый буфер и передаёт дескриптор в ring buffer. Отдельная высокоприоритетная DSP-задача обрабатывает данные.

**Плюсы**
- получение отделено от вычислений;
- можно использовать небольшие блоки;
- весь DSP не выполняется в ISR;
- можно разделить RX/TX и управление.

**Минусы**
- нужно управлять очередью и backpressure;
- приоритет задачи влияет на worst-case latency;
- синхронизация state и переключения RX/TX требуют отдельного протокола.

**Оценка:** хороший компромисс, особенно если I2S DMA будет собирать аудио, а отдельная задача — обрабатывать блоки.

## 5. Возможное распределение задач

- Acquisition: получение и маркировка блоков ADC/IQ.
- DSP RX: CIC/Hilbert/demod/AGC/filter/audio output.
- DSP TX: mic filter/IQ/phase/amplitude.
- RF output: команды Si5351 и PWM.
- Control/UI: кнопки, OLED, настройки.

Не нужно автоматически закреплять каждую задачу за отдельным ядром. Сначала измерить производительность и блокировки.

## 6. Предварительная рекомендация

Проектировать DSP как блоково-обрабатываемое ядро с явным состоянием и отдельным аппаратным producer/consumer. При этом сохранить возможность тестировать те же алгоритмы по одному IQ sample.

Предлагаемый внешний интерфейс должен поддерживать:
- входные выборки с явной последовательностью I/Q;
- количество sample frames;
- постоянное состояние фильтров между блоками;
- выдачу выходного аудиоблока;
- отдельное получение TX sample и выдачу frequency_delta + amplitude.

Окончательные сигнатуры пока не выбирать до выяснения ADC timing, выравнивания I/Q и формата тестовых данных.

## 7. Варианты формата входа RX

### RX input 1 — исходные чередующиеся ADC events
Каждый элемент содержит channel I/Q, sample и порядковый номер/временную метку. DSP воспроизводит временную модель и интерполяцию I.

### RX input 2 — массивы I[] и Q[]
Требуется определить, являются ли пары одновременными или смещёнными по времени. Если пары уже выровнены, исходную коррекцию I нужно осмысленно преобразовать, а не просто удалить.

### RX input 3 — source-aligned I/Q pairs
Адаптер выполняет точное согласование, DSP получает упорядоченные пары. Это удобно, но граница между адаптером и DSP должна быть документирована.

Ни один вариант пока не утверждён. Главный критерий — совпадение фазовой характеристики и подавления боковой полосы.

## 8. Этапы до реализации

1. Сделать host-side эталонную модель активного RX/TX.
2. Подготовить тестовые входные данные и контрольные выходы.
3. Проверить арифметику AVR/ESP32.
4. Определить фактический источник ADC/IQ для платы.
5. Измерить задержку и пропускную способность блока.
6. После этого зафиксировать API DSP и расписание.

Этот документ фиксирует варианты, а не окончательное решение.
