# TX — подробный разбор передающего SSB-тракта

**Источник:** PE1NNZ uSDX, commit bf8acd31b8a2506c4e1d203dfb283feecae947e1.  
**Статус:** структура активного SSB TX восстановлена; численная проверка впереди.

## 1. Частоты и шкалы

- F_SAMP_TX = 4800 — частота TX sample cycles.
- Период цикла: 208,333 мкс.
- _UA = 600 — единиц на полный оборот фазы.
- При стандартном F_MCU=20 MHz используется _F_SAMP_TX=4800.
- Одна единица dp соответствует 4800 / 600 = 8 Hz изменения частоты.

Если F_MCU отличается от 20 MHz, _F_SAMP_TX масштабируется формулой исходника. Это параметр исходной AVR-системы, не частота ESP32.

Ссылка: [частотные параметры TX](https://github.com/threeme3/usdx/blob/bf8acd31b8/usdx.ino#L1920-L1935).

## 2. Активная конфигурация SSB

- MULTI_ADC = 1 — несколько ADC-преобразований на микрофонный отсчёт.
- MORE_MIC_GAIN = 1 — активна улучшенная ветка микрофонной фильтрации.
- DIG_MODE закомментирован.
- CARRIER_COMPLETELY_OFF_ON_LOW = 1.
- MAX_DP определён.
- QUAD закомментирован.
- MIC_ATTEN = 0.

Это ветка, которую следует воспроизводить первой.

## 3. Получение микрофонного отсчёта

F_ADC_CONV = 192307/2 — параметр настройки ADC. В start_rx() отдельный ADC-канал микрофона настраивается с F_ADC_CONV*4; комментарий исходника говорит о более высокой частоте conversion для TX.

В dsp_tx() активен MULTI_ADC:
1. Берётся текущее значение ADC.
2. Запускается очередное преобразование.
3. Отправляются ранее рассчитанные регистры PLL Si5351.
4. Обновляется PWM амплитуда из предыдущего результата DSP.
5. Считываются следующие результаты ADC и запускаются новые преобразования.
6. ssb() вызывается с ранее собранным _adc.
7. Рассчитываются новые PLL-регистры.
8. Несколько ADC результатов усредняются; новое _adc используется следующим вызовом.

В коде четыре значения суммируются и нормируются выражением adc/4 - (512 - AF_BIAS), где AF_BIAS=32. Эти четыре ADC readings неравномерны по времени: первое чтение и запуск следующей конверсии идут до SendPLLRegisterBulk(), второе чтение — после передачи PLL-регистров (в комментарии указано около 88 мкс), третье — после вызова ssb(), четвёртое — после freq_calc_fast(). Следовательно, это не обычный uniform 4x oversampling block. Точную последовательность нужно воспроизвести в reference harness; подробности: [09_ADC_TIMING.md](09_ADC_TIMING.md).

Это конвейер с задержкой: текущий вызов DSP использует _adc, сформированный предыдущим циклом, пока новый микрофонный отсчёт готовится.

Фактическую длительность каждого ADC conversion нужно отдельно перепроверить по настройке делителя и временной диаграмме AVR. Параметр F_ADC_CONV*4 нельзя автоматически трактовать как гарантированную фактическую частоту отсчётов.

Ссылки: [ADC setup](https://github.com/threeme3/usdx/blob/bf8acd31b8/usdx.ino#L3265-L3293), [start_rx](https://github.com/threeme3/usdx/blob/bf8acd31b8/usdx.ino#L3538-L3555), [dsp_tx](https://github.com/threeme3/usdx/blob/bf8acd31b8/usdx.ino#L2040-L2110).

## 4. Микрофонная фильтрация и I/Q

ssb(int16_t in) хранит:
- dc — состояние среднего для удаления DC;
- z1 — состояние фильтра;
- v[16] — история микрофонных отсчётов.

При активном MORE_MIC_GAIN и выключенном DIG_MODE:
1. Удвоение входа для компенсации потерь.
2. Фильтрация с состоянием z1.
3. Удаление DC через dc.
4. Запись результата в v[15].
5. I формируется из v[7]*2.
6. Q формируется FIR Hilbert по парным отсчётам v[0], v[2], ..., v[14].

Комментарий исходника к Hilbert TX заявляет около 40 dB sideband rejection в области 400–1900 Hz при 4 kSPS. Частота TX в коде — 4,8 kSPS; характеристику на реальных 4,8 kSPS нужно измерить.

## 5. Амплитудная ветвь

magn(i,q) использует приближение:

    max(abs(i),abs(q)) + min(abs(i),abs(q))/4

Комментарий указывает ошибку около 0,95 dB относительно sqrt(i*i+q*q).

Далее:
- амплитуда сдвигается на drive;
- ограничивается значением 255;
- проходит через lut[256];
- при активном TX результат записывается в amp, иначе — ноль.

LUT создаётся build_lut() на основе pwm_min и pwm_max. В dsp_tx() amp передаётся в OCR1BL — PWM управления PA.

## 6. Фазовая ветвь

Фаза вычисляется в arctan3(q,i), использующей приближение atan2. Комментарий указывает ошибку около 0,8 градуса.

Далее:
- prev_phase хранит предыдущую фазу;
- dp = phase - prev_phase;
- отрицательный dp переводится в положительную сторону добавлением _UA;
- MAX_DP ограничивает максимальную разность и корректирует prev_phase;
- при USB возвращается dp * (_F_SAMP_TX / _UA);
- в остальных ветках знак меняется.

При _F_SAMP_TX=4800 и _UA=600 множитель равен 8 Hz на единицу dp.

dp — управляющая частотная разность, не сама несущая частота.

## 7. Передача команды на Si5351

dsp_tx() вызывает:
- si5351.freq_calc_fast(df) — расчёт новых регистров;
- si5351.SendPLLRegisterBulk() — отправка регистров по I2C.

В начале следующего TX-цикла отправляются подготовленные ранее PLL-регистры. Исходник использует конвейер подготовки и передачи команд. Комментарий указывает около 88 мкс на bulk I2C transfer при скорости 731 kbit/s и отдельно отмечает время установления PLL loop filter.

При переносе:
- арифметика ssb() выдаёт численные df и amp;
- адаптер Si5351 получает готовую частотную команду;
- порядок и задержка выдачи команд явно документируются и тестируются;
- блокирующий I2C-вызов нельзя автоматически оставлять внутри high-priority audio handler ESP32.

## 8. Объём первого SSB TX port

В первую реализацию DSP_TX включить:
- микрофонный pre-filter и DC removal;
- 16-sample history;
- I/Q Hilbert;
- amplitude approximation;
- approximate atan2;
- phase difference, wrap, MAX_DP;
- выход frequency_delta и amplitude.

Отдельно, не смешивая с SSB TX:
- CW tone generation process_minsky();
- AM dsp_tx_am();
- FM dsp_tx_fm();
- key-click shaping.

Это возможные последующие этапы.

## 9. Проверки TX

1. Подать известную цифровую синусоиду вместо ADC.
2. Сверить микрофонный pre-filter.
3. Сверить I/Q Hilbert.
4. Сверить magn(), arctan3(), phase, dp и df.
5. Проверить переход через 0/полный оборот фазы.
6. Проверить MAX_DP.
7. Сверить amplitude/PWM values.
8. На уровне аппаратного адаптера измерить latency I2C и соответствие частотной команды её фактическому применению.

## 10. Важная семантика макроса _atan2

В исходнике задано:

    #define _atan2(z) (_UA/8 + _UA/22 - _UA/22 * z) * z

Вызов выглядит так:

    _atan2(abs(q) / abs(i))

Это function-like macro, а не функция. Препроцессор подставляет выражение z текстуально. Поэтому раскрытый код не эквивалентен варианту, где сначала вычисляется целочисленная переменная:

    z = abs(q) / abs(i);
    result = (A + B - C*z) * z;

В раскрытом выражении умножения и деления выполняются слева направо с одинаковым приоритетом, например:

    (A + B - C * abs(q) / abs(i)) * abs(q) / abs(i)

То есть коэффициент C умножает числитель до деления. Это существенно для целочисленной точности: если сначала вычислить abs(q)/abs(i) как int, дробная часть будет потеряна и результат станет грубо ступенчатым.

При переносе:
- не вычислять z отдельным целочисленным отношением без отдельного обоснования;
- сохранить исходный порядок умножений/делений и фактическую ширину промежуточного int;
- отдельно проверить AVR signed overflow/range;
- сравнить source-equivalent integer expansion, wide integer variant и float/double variant на одном наборе I/Q vectors.

Это один из обязательных golden tests для TX phase path.
