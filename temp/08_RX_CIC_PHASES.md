# RX CIC — фазовое расписание и эквивалентная передаточная функция

**Источник:** PE1NNZ uSDX, commit bf8acd31b8a2506c4e1d203dfb283feecae947e1.  
**Активная ветка:** NEW_RX=1, SIMPLE_RX выключен.  
**Назначение:** точно зафиксировать расписание восьми функций и математику децимации.

## 1. Что означают два каскадных этапа

В активном коде коэффициенты каждого decimate-by-2 этапа соответствуют:

    h2[n] = [1, 3, 3, 1]

Для первого этапа:

    u[m] = x[2m] + 3*x[2m-1] + 3*x[2m-2] + x[2m-3]

Для второго этапа, который работает уже на половинной частоте:

    y[k] = u[2k] + 3*u[2k-1] + 3*u[2k-2] + u[2k-3]

Итоговый коэффициент изменения частоты — 4. Если выразить оба каскада на исходной частоте, передаточная функция:

    H(z) = (1 + z^-1)^3 * (1 + z^-2)^3
         = (1 + z^-1 + z^-2 + z^-3)^3

Это CIC N=3, R=4. Эквивалентная импульсная последовательность до децимации:

    [1, 3, 6, 10, 12, 12, 10, 6, 3, 1]

Это математическое следствие формул активного кода; в исходнике вычисления распределены по фазам, а не записаны одной свёрткой.

## 2. Восемь таймерных фаз

Каждое событие таймера вызывает одну функцию. Четыре события относятся к I, четыре — к Q.

| Фаза | Функция | Канал | Действия первой ступени | Действия второй ступени |
|---:|---|---|---|---|
| 0 | sdr_rx_00 | I | Вычисляет текущий even-выход uI из текущего I и истории | Вычисляет итоговый yI; вызывает process(yI, q_ac2); сохраняет even history второй ступени |
| 1 | sdr_rx_01 | Q | Сдвигает q_s0zb1=q_s0zb0; q_s0zb0=ac | — |
| 2 | sdr_rx_02 | I | Сдвигает i_s0zb1=i_s0zb0; i_s0zb0=ac | — |
| 3 | sdr_rx_03 | Q | Вычисляет очередной промежуточный uQ | Сохраняет его в q_s1zb0, сдвигает q_s1zb1 |
| 4 | sdr_rx_04 | I | Вычисляет очередной промежуточный uI | Сохраняет его в i_s1zb0, сдвигает i_s1zb1 |
| 5 | sdr_rx_05 | Q | Сдвигает q_s0zb1=q_s0zb0; q_s0zb0=ac | — |
| 6 | sdr_rx_06 | I | Сдвигает i_s0zb1=i_s0zb0; i_s0zb0=ac | — |
| 7 | sdr_rx_07 | Q | Вычисляет текущий even-выход uQ из текущего Q и истории | Вычисляет итоговый yQ и сохраняет q_ac2 |

И затем расписание возвращается к фазе 0.

## 3. Формулы active I phases

Условные обозначения:
- x — текущий I ADC sample, возвращённый sdr_rx_common_i().
- a1 — состояние i_s0za1.
- b0/b1 — состояния i_s0zb0/i_s0zb1.
- c1/d0/d1 — состояния i_s1za1/i_s1zb0/i_s1zb1.

Первая ступень для even-фазы (sdr_rx_00):

    uI_even = (x + 3*(a1 + b0) + b1) >> 1

Далее в той же фазе рассчитывается выход второй ступени:

    yI = uI_even + 3*(c1 + d0) + d1

И обновляется even history:
- i_s0za1 = x
- i_s1za1 = uI_even

На фазе sdr_rx_02 обновляется odd history первой ступени:
- i_s0zb1 = i_s0zb0
- i_s0zb0 = x

На фазе sdr_rx_04 рассчитывается промежуточный odd-выход первой ступени:

    uI_odd = (x + 3*(i_s0za1 + i_s0zb0) + i_s0zb1) >> 1

Затем:
- i_s1zb1 = i_s1zb0
- i_s1zb0 = uI_odd
- i_s0za1 = x

На фазе sdr_rx_06 снова обновляется odd history первой ступени:
- i_s0zb1 = i_s0zb0
- i_s0zb0 = x

Обрати внимание: uI_even используется сразу для расчёта yI, а uI_odd сохраняется для следующего выхода второй ступени.

## 4. Формулы active Q phases

Q-ветвь аналогична, но её фазы сдвинуты относительно I.

На фазе sdr_rx_01:
- q_s0zb1 = q_s0zb0
- q_s0zb0 = x

На фазе sdr_rx_03 рассчитывается промежуточный odd-выход первой ступени:

    uQ_odd = (x + 3*(q_s0za1 + q_s0zb0) + q_s0zb1) >> 1

Затем:
- q_s1zb1 = q_s1zb0
- q_s1zb0 = uQ_odd
- q_s0za1 = x

На фазе sdr_rx_05:
- q_s0zb1 = q_s0zb0
- q_s0zb0 = x

На фазе sdr_rx_07 рассчитываются even-выход первой ступени и итоговый выход второй:

    uQ_even = (x + 3*(q_s0za1 + q_s0zb0) + q_s0zb1) >> 1

    q_ac2 = uQ_even + 3*(q_s1za1 + q_s1zb0) + q_s1zb1

Затем:
- q_s0za1 = x
- q_s1za1 = uQ_even

q_ac2 становится готовым Q-значением для следующего вызова process() на фазе I.

## 5. Где рождается выходная пара I/Q

Финальный Q-результат вычисляется на фазе 7. Следующий вызов — фаза 0 I — рассчитывает yI и вызывает:

    process(yI, q_ac2)

Поэтому process() вызывается один раз за восемь timer events:

    62500 / 8 = 7812.5 pair/s

Именно на этом уровне далее выполняются Hilbert, задержка I и slow_dsp().

## 6. Временное совмещение каналов

Логическое расписание входных каналов чередуется:

    I, Q, I, Q, I, Q, I, Q, ...

I и Q поступают с временным смещением в один timer slot. В активной I-функции sdr_rx_common_i() выполняется усреднение предыдущего и текущего I sample:

    corr_adc = (prev_adc + adc) / 2

Интерпретация: усреднение двух соседних I-значений оценивает I в середине интервала между ними, что и нужно для совмещения с чередующимся Q-потоком. Это согласуется с комментарием исходника о linear interpolation для коррекции I/Q sample delay.

Точную временную метку аналогового ADC aperture нужно ещё сверить с pipeline запуска преобразования и чтения регистра ADC. Поэтому интерпретация midpoint зафиксирована как математически согласованная с кодом, а окончательная абсолютная привязка остаётся открытой задачей.

## 7. Почему нельзя просто заменить это готовым CIC

DSP библиотека может дать те же коэффициенты и rate change, но результат всё ещё может отличаться из-за:
- другой фазы decimation;
- другого порядка начальных состояний;
- другого масштабирования/сдвига;
- другого временного отношения I/Q;
- другого поведения целочисленной арифметики.

На host-side reference model нужно сравнить выходы после каждой ступени и итоговые I/Q пары, а не только частотную характеристику «в среднем».

## 9. Проверка коэффициентного усиления

Для постоянного входного значения сумма коэффициентов одного FIR-этапа [1,3,3,1] равна 8.

В активной реализации:
- первая ступень сдвигает результат вправо на M_SR=1, поэтому её steady-state DC gain равен 8/2 = 4;
- вторая ступень не выполняет дополнительного сдвига, её gain равен 8;
- общий raw CIC gain до att2 равен 4*8 = 32.

Затем process() выполняет i_ac2 >>= att2 и q_ac2 >>= att2. При начальном att2=2 это ещё деление на 4, поэтому арифметически ожидаемый steady-state gain на вход Hilbert после этих сдвигов равен 8.

Рядом с определением R=4 исходник содержит комментарий «providing 12dB gain». Он не совпадает напрямую с приведённым подсчётом raw coefficient gain. Возможно, комментарий описывает иной уровень нормировки/сравнения. Это расхождение нужно проверить на эталонной реализации и не использовать 12 dB как коэффициент масштабирования без проверки.
