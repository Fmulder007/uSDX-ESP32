# DSP — состояние, буферы и временная модель

**Источник:** PE1NNZ uSDX, commit bf8acd31b8a2506c4e1d203dfb283feecae947e1.  
**Назначение:** подготовить перенос скрытого static-состояния в явные контексты DSP.

## 1. Частотная таблица

| Контекст | Частота | Период |
|---|---:|---:|
| RX Timer2 events | 62 500 Hz | 16 мкс |
| RX I samples | 31 250 Hz | 32 мкс |
| RX Q samples | 31 250 Hz | 32 мкс |
| RX decimated I/Q pairs | 7 812,5 Hz | 128 мкс |
| RX PWM carrier | 78 125 Hz | 12,8 мкс |
| RX PWM duty updates | 31 250 Hz | 32 мкс |
| TX SSB timer cycles | 4 800 Hz | 208,333 мкс |

В таблице указаны номинальные целевые частоты. Исходник после проверки Arduino F_CPU=16 MHz переопределяет F_CPU на 20.007 MHz, а OCR рассчитывается целочисленно. При стандартных настройках реальные значения: RX timer 62 521,875 Hz, I/Q пары 7 815,234 Hz, TX timer 4 809,375 Hz, PWM carrier 78 152,344 Hz. Подробный расчёт — в [09_ADC_TIMING.md](09_ADC_TIMING.md). Это частоты исходной модели uSDX, а не требуемые частоты периферии ESP32.

## 2. RX — состояние CIC и расписание

Глобальное состояние RX:
- func_ptr — текущий обработчик фазы расписания.
- rx_state — состояние последовательности.
- admux[] — настройки выбора ADC channel.
- i_s0za1/i_s0zb0/i_s0zb1, i_s1za1/i_s1zb0/i_s1zb1 — история CIC I.
- q_s0za1/q_s0zb0/q_s0zb1, q_s1za1/q_s1zb0/q_s1zb1 — история CIC Q.
- q_ac2 — последняя подготовленная Q-выборка после CIC.
- att2 — цифровое ослабление.

Локальное static-состояние:
- prev_adc в sdr_rx_common_i() — предыдущая I-выборка для временного выравнивания.
- v[14] в process() — история Q Hilbert.
- v[7] в process() — задержка I.
- ac3, ozd1, ozd2 — состояние аудиовыходной Comb-секции.
- ozi1, ozi2 — интеграторы выходной интерполяции.
- absavg256 и счётчик — статистика уровня.

Часть состояния находится глобально, часть — в локальных static. При переносе их нужно собрать в явный RxDspState: чтобы можно было предсказуемо инициализировать фильтры, создавать тестовый экземпляр, избегать скрытой зависимости от порядка запуска и сравнивать разные тестовые потоки.

## 3. TX — переменные и буферы

Состояние SSB:
- dc, z1 — микрофонная фильтрация и удаление DC.
- v[16] — история микрофона для Hilbert.
- prev_phase — фаза предыдущего отсчёта.
- amp — рассчитанное значение амплитуды.
- lut[256] — таблица преобразования амплитуды в PWM уровень.
- drive, vox_thresh, tx, mode, filt — runtime параметры/управляющие состояния.
- _adc — конвейерный усреднённый микрофонный отсчёт для следующего цикла.
- quad используется только при включённом QUAD, выключенном в выбранной конфигурации.

Состояние аппаратного уровня (PLL registers, PWM compare register и переключение TX/RX) должно быть отдельно от математического состояния DSP_TX.

## 4. RX — ISR и повторное разрешение прерываний

TIMER2_COMPA_vect выполняет func_ptr().

В process():
- tc — счётчик вложенности/защита от рекурсии.
- При входе, если tc++ == 0, код вызывает interrupts().
- Это разрешает следующему таймерному событию обслужить очередные I/Q-фазы, пока текущая постобработка ещё не завершилась.
- В конце выполняется tc--.

Комментарий автора: slow_dsp может занимать больше одного RX sample interval, поэтому допускаются последующие прерывания для сбора следующей выборки; повторное вложение обработки ограничивается tc.

Это AVR-специфическая схема с повторно разрешаемыми прерываниями внутри ISR. Её нельзя переносить буквально на ESP32. Нужно сохранить throughput и ограничить задержку/очередь данных другим способом.

## 5. Бюджеты времени

Теоретические интервалы:
- 16 мкс между RX timer events;
- 32 мкс между отсчётами одного RX-канала;
- 128 мкс между парами после CIC;
- 208,33 мкс между TX cycles.

При CPU 240 MHz арифметический верхний ориентир: 3 840 тактов за 16 мкс, 30 720 тактов за 128 мкс, около 50 000 тактов за TX cycle 208,33 мкс. Это только арифметический бюджет, не подтверждённое время доступное DSP: ограничения зависят от источника выборок, прерываний, DMA, RTOS и других задач.

Измерить:
- длительность каждой RX-фазы;
- длительность обработки пары I/Q;
- worst-case latency;
- длительность TX DSP;
- задержку от расчёта до обновления Si5351;
- число пропусков/переполнений при длительном потоке.

## 6. Разделение вычислений для ESP32

### Получение выборок
Узкий ISR или DMA callback фиксирует выборки/дескрипторы и последовательность. Не выполняет UI, Serial, файлы или блокирующий I2C.

### DSP-поток
Выполняет CIC, Hilbert, demod, AGC, NR, IIR и TX math. Использует заранее выделенные контексты и буферы, не выделяет память на каждом отсчёте и не зависит от OLED/меню/радиочастотного драйвера.

### Вывод и управление
Принимает готовые аудиоблоки и команды Si5351/PWM. Управляет аппаратурой и сообщает статус/ошибки, не блокируя критический поток.

## 7. Что измерить, а не предположить

- deadline на блок при выбранном размере;
- worst-case execution time RX и TX;
- jitter получения ADC samples;
- задержку между I и Q;
- latency от расчёта df до фактического обновления Si5351;
- допустимую глубину очередей;
- поведение при переполнении DMA/ring buffer;
- длительную устойчивость без аудиопропусков.

## 8. Жизненный цикл состояния при переключении RX/TX

В исходнике важно различать полный reset при включении MCU и подготовку RX после переключения режимов.

При start_rx():
- rx_state устанавливается в 0;
- func_ptr устанавливается на sdr_rx_00;
- _init устанавливается в 1;
- повторно настраиваются ADC mux и таймеры.

При возврате из TX в RX switch_rxtx() также сбрасывает rx_state и устанавливает _init=1.

Для активного NEW_RX при первом I-цикле:
- sdr_rx_common_i() при _init обнуляет ocomb, ozi1, ozi2;
- process() при _init обнуляет ac3, ozd1, ozd2 и снимает _init.

Но в активной ветке нет явного сброса:
- CIC-регистров i_s*/q_s* и q_ac2;
- Hilbert history v[14];
- I-delay history v[7];
- внутренних static состояний slow_dsp(), AGC/NR и filt_var().

Следовательно, при обычном переключении TX→RX часть истории DSP сохраняется через интервал TX. На холодном старте static/global storage обнулена, но это не эквивалентно повторному reset при каждом возврате в RX.

Это факт наблюдаемой структуры исходника; намеренность такого поведения отдельно не доказана. При портировании нужно иметь явно описанные операции:
- cold_init() — начальная инициализация всего DSP state;
- rx_resume_source_compatible() — поведение, соответствующее исходному переключению TX→RX;
- rx_reset_full() — полный сброс всех RX фильтров, если он будет нужен как отдельный режим.

Не подменять source-compatible resume полным reset без отдельного сравнения переходного процесса.

## 9. Расширенный перечень DSP state

Ниже перечислено состояние, которое должно быть явно найдено и назначено владельцу в новом ядре. Это не означает, что все режимные ветви включены одновременно.

### RX — CIC и временная организация

| Состояние | Назначение |
|---|---|
| rx_state, func_ptr | фаза расписания ISR |
| i_s0za1, i_s0zb0, i_s0zb1 | история первой decimate-by-2 ступени I |
| i_s1za1, i_s1zb0, i_s1zb1 | история второй ступени I |
| q_s0za1, q_s0zb0, q_s0zb1 | история первой ступени Q |
| q_s1za1, q_s1zb0, q_s1zb1 | история второй ступени Q |
| q_ac2 | последний подготовленный Q результат |
| prev_adc | предыдущий I ADC результат для midpoint interpolation |

### RX — квадратурная обработка и аудиовыход

| Состояние | Назначение |
|---|---|
| v[14] внутри process() | история Q для Hilbert |
| v[7] внутри process() | задержка I для совмещения с Q Hilbert |
| qh | текущая Hilbert quadrature result |
| ac3 | предыдущий sample на входе выходной Comb-секции |
| ozd1, ozd2 | история Comb-дифференциаторов |
| ocomb | промежуточный результат для интеграторной части |
| ozi1, ozi2 | интеграторные состояния выходного interpolator |
| tc | защита от повторного вложения process() |

### RX — постобработка

| Состояние | Назначение |
|---|---|
| gain | fast AGC gain state |
| centiGain, decayCount, small | alternative AGC state, используемый если включён соответствующий режим |
| ea1 | exponential average state NR |
| dc в AM branch | DC removal state AM detector |
| zi в FM branch | предыдущий I value FM detector |
| za1, za2, zb*, zc* в filt_var() | IIR filter delay/feedback state |
| zz1, zz2 в filt_var() | состояние SSB high-pass section |
| absavg256, absavg256cnt | статистика уровня |

### TX SSB

| Состояние | Назначение |
|---|---|
| dc, z1 внутри ssb() | mic DC removal и LPF state |
| v[16] внутри ssb() | микрофонная история для Hilbert |
| prev_phase внутри ssb() | предыдущая фаза |
| _adc | конвейерный усреднённый микрофонный sample |
| amp | рассчитанная амплитуда |
| lut[256] | amplitude-to-PWM lookup table |
| drive, vox_thresh | runtime параметры микрофонной чувствительности/усиления |
| quad | только для опционального QUAD пути |

### Параметры конфигурации — не фильтровое состояние

К этой группе относятся mode, filt, agc, nr, att2, volume, drive, MAX_DP и параметры аппаратного режима. Их нужно передавать в DSP через конфигурацию, а не маскировать как глобальные переменные внутри математических функций.

В новом коде желательно иметь отдельные структуры RxDspState, TxDspState, AudioOutState и DspConfig. Конкретную раскладку полей утвердить после reference harness.
