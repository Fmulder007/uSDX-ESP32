# DSP — состояние, буферы и временная модель

**Источник:** PE1NNZ uSDX, commit bf8acd31b8a2506c4e1d203dfb283feecae947e1.  
**Назначение:** подготовить перенос скрытого static-состояния в явные контексты DSP.

## 1. Частотная таблица

| Контекст | Частота | Период |
|---|---:|---:|
| RX Timer2 events | 62 500 Hz | 16 мкс |
| RX I samples | 31 250 Hz | 32 мкс |
| RX Q samples | 31 250 Hz | 32 мкс |
| RX decimated I/Q pairs | 7 812,5 Hz | 128 мкс |
| RX PWM carrier | 78 125 Hz | 12,8 мкс |
| RX PWM duty updates | 31 250 Hz | 32 мкс |
| TX SSB timer cycles | 4 800 Hz | 208,333 мкс |

Это частоты исходной модели uSDX, а не требуемые частоты периферии ESP32.

## 2. RX — состояние CIC и расписание

Глобальное состояние RX:
- func_ptr — текущий обработчик фазы расписания.
- rx_state — состояние последовательности.
- admux[] — настройки выбора ADC channel.
- i_s0za1/i_s0zb0/i_s0zb1, i_s1za1/i_s1zb0/i_s1zb1 — история CIC I.
- q_s0za1/q_s0zb0/q_s0zb1, q_s1za1/q_s1zb0/q_s1zb1 — история CIC Q.
- q_ac2 — последняя подготовленная Q-выборка после CIC.
- att2 — цифровое ослабление.

Локальное static-состояние:
- prev_adc в sdr_rx_common_i() — предыдущая I-выборка для временного выравнивания.
- v[14] в process() — история Q Hilbert.
- v[7] в process() — задержка I.
- ac3, ozd1, ozd2 — состояние аудиовыходной Comb-секции.
- ozi1, ozi2 — интеграторы выходной интерполяции.
- absavg256 и счётчик — статистика уровня.

Часть состояния находится глобально, часть — в локальных static. При переносе их нужно собрать в явный RxDspState: чтобы можно было предсказуемо инициализировать фильтры, создавать тестовый экземпляр, избегать скрытой зависимости от порядка запуска и сравнивать разные тестовые потоки.

## 3. TX — переменные и буферы

Состояние SSB:
- dc, z1 — микрофонная фильтрация и удаление DC.
- v[16] — история микрофона для Hilbert.
- prev_phase — фаза предыдущего отсчёта.
- amp — рассчитанное значение амплитуды.
- lut[256] — таблица преобразования амплитуды в PWM уровень.
- drive, vox_thresh, tx, mode, filt — runtime параметры/управляющие состояния.
- _adc — конвейерный усреднённый микрофонный отсчёт для следующего цикла.
- quad используется только при включённом QUAD, выключенном в выбранной конфигурации.

Состояние аппаратного уровня (PLL registers, PWM compare register и переключение TX/RX) должно быть отдельно от математического состояния DSP_TX.

## 4. RX — ISR и повторное разрешение прерываний

TIMER2_COMPA_vect выполняет func_ptr().

В process():
- tc — счётчик вложенности/защита от рекурсии.
- При входе, если tc++ == 0, код вызывает interrupts().
- Это разрешает следующему таймерному событию обслужить очередные I/Q-фазы, пока текущая постобработка ещё не завершилась.
- В конце выполняется tc--.

Комментарий автора: slow_dsp может занимать больше одного RX sample interval, поэтому допускаются последующие прерывания для сбора следующей выборки; повторное вложение обработки ограничивается tc.

Это AVR-специфическая схема с повторно разрешаемыми прерываниями внутри ISR. Её нельзя переносить буквально на ESP32. Нужно сохранить throughput и ограничить задержку/очередь данных другим способом.

## 5. Бюджеты времени

Теоретические интервалы:
- 16 мкс между RX timer events;
- 32 мкс между отсчётами одного RX-канала;
- 128 мкс между парами после CIC;
- 208,33 мкс между TX cycles.

При CPU 240 MHz арифметический верхний ориентир: 3 840 тактов за 16 мкс, 30 720 тактов за 128 мкс, около 50 000 тактов за TX cycle 208,33 мкс. Это только арифметический бюджет, не подтверждённое время доступное DSP: ограничения зависят от источника выборок, прерываний, DMA, RTOS и других задач.

Измерить:
- длительность каждой RX-фазы;
- длительность обработки пары I/Q;
- worst-case latency;
- длительность TX DSP;
- задержку от расчёта до обновления Si5351;
- число пропусков/переполнений при длительном потоке.

## 6. Разделение вычислений для ESP32

### Получение выборок
Узкий ISR или DMA callback фиксирует выборки/дескрипторы и последовательность. Не выполняет UI, Serial, файлы или блокирующий I2C.

### DSP-поток
Выполняет CIC, Hilbert, demod, AGC, NR, IIR и TX math. Использует заранее выделенные контексты и буферы, не выделяет память на каждом отсчёте и не зависит от OLED/меню/радиочастотного драйвера.

### Вывод и управление
Принимает готовые аудиоблоки и команды Si5351/PWM. Управляет аппаратурой и сообщает статус/ошибки, не блокируя критический поток.

## 7. Что измерить, а не предположить

- deadline на блок при выбранном размере;
- worst-case execution time RX и TX;
- jitter получения ADC samples;
- задержку между I и Q;
- latency от расчёта df до фактического обновления Si5351;
- допустимую глубину очередей;
- поведение при переполнении DMA/ring buffer;
- длительную устойчивость без аудиопропусков.
